# BR1987 — a Spring Boot workspace ran the Node toolchain, and a missing package.json was counted as a defect of the app

Scope: BR1987 only, inside the frozen audit boundary 1951..2105. Branched from origin/main `f5ed48ddc` (BR1986 setup-failure scoring / complete-build matcher, #4256). Read only via `get_build_report` — no remote autopsy write, no replay, no deploy, no provider call. `src/server/AI/RouterOne/*` and Pro Chain V2 admission were not touched.

## What the user asked

Generic summary: a request for a battle-royale style map game with a login screen and a world map of continents and islands. Distinctive request details, account/workspace/session/history/build identifiers, and precise event timestamps are omitted from public evidence.

## Event sequence (wall-clock timestamps omitted)

1. **Stage.** The workspace framework was Spring Boot. The durable tree held only the four-file Spring Boot starter (a POM, the application class, a hello controller, and application properties). The turn was first read as an edit, then flipped to a fresh build because the durable tree held only that starter.
2. **Stage.** The fast lane always ran `npm install --no-audit --no-fund` (with the legacy-peer-deps fallback), then `npm run dev`, then probed the Vite port. There was no package.json, so the install failed ENOENT and was recorded as a failed sandbox command. The release gate counted that as a build-breaking blocker of the app and flipped a success verdict to not ok.
3. **Stage.** The later platform preview path skipped the start, with the reason that there was no package.json and therefore nothing to run a dev server from. That skip is right for a bare HTML page, but wrong for a Spring Boot app whose registry start command is already `mvn spring-boot:run` on port 8080. The health-check also treated a missing package.json as a stale Node tree and ran npm install again. Sandbox typecheck was still requested on a tree with no TypeScript.
4. **Stage.** An unterminated PNG tail was offered back to the fast-lane continuation. A later binary-as-text write was refused. Completed binary blocks were already refused on this path; an open binary tail was not dropped first.

Outcome **failed** (`ok=false`). The user was not charged (working-app-or-free). Markup was also waived because a preview never came up. The failure was the Node toolchain and the release gate, not a defect in the user's request.
