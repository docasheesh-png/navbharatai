The workspace already had files, so `BUILD_ORDER_READ_AS_EDIT` turned the build-order into an edit (`PROJECT_MODE`: “not a fresh build, so no plan was created”). The builder produced an examination-assistant UI (class selection 9–12, subjects, MCQ practice, AI chat, study materials, dashboard). It typechecked, rendered in a real browser at 711 s (`IN_BUILD_GREEN`, 21 files), and the explorer repaired one broken “View Material” control. `RELEASE_GATE` stayed YELLOW: no save-and-reload journey was proven (`JOURNEY_NOT_RUN` — the form fields were not on the running page), and the phone check failed.

Opened at 390×844 (touch), the page scrolled SIDEWAYS by 119 px: `<header class="nb-topbar">` “EDU AI – EXAMINATION ASSISTANT” was 508 px wide. The kit drew `.nb-topbar` as `display: flex` with nothing letting it shrink — a flex item’s `min-width` is its content size — so the long title widened the page. BR1959 already gave `.nb-header-actions` and `.nb-chips` `min-width: 0; max-width: 100%` (and wrap / inner scroll) after a 990 px school-nav overflow; `.nb-toolbar` already wraps on a phone; `.nb-main` already has `min-width: 0`. `.nb-topbar` was the missed sibling. This PR adds the same shrink/wrap tokens, plus `box-sizing: border-box` (so padding is inside `max-width: 100%`) and `overflow-x: auto` (so a title that still cannot wrap scrolls inside the bar instead of the page).

Existing shipped apps are not rewritten. Only new kit copies pick up the rule. `kitRestore` appends a *dropped* current rule; it does not overwrite an older `.nb-topbar` block the app still has. `mobileLayoutCheck` is not taught to ignore user headers (and is not taught to ignore `[data-nbai-signature]` — that stays Q-2641’s shipped CSS, already merged). This does not claim the historical examination-assistant app was repaired.

The recap says “Fully responsive design that works on both mobile and desktop” and “fully functional and ready for use” while `MOBILE_LAYOUT_ISSUES` fired and the journey was not run. Those size phrases are not `SIZE_CLAIMED` today — the same class as Q-2611 (“works across all device sizes”). Q-2611 is not rewritten and is not shipped: widening `claimAudit` needs the admin decision that row already asks for, plus an opposite-class corpus of apps with `MOBILE_LAYOUT_OK` that truthfully claim they are responsive.

`GAME_PLAYTEST_NOT_RUN` called this a “quiz game” because the MCQs are drawn in the page, not on a canvas. `APP_SCOPE` stayed an ordinary one-shot and domain stayed `general` (not game). Do not escalate examination/MCQ/assistant to `domain=game` (education apps must stay not-games; the opposite-class would be huge). Canvas-less playtest widening is already Q-2634.
