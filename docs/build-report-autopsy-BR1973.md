Reviewer FAIL on PR #4164 at `9a39ae210`: the first `study[\s-]?apps?` pattern also matched “case study app”, “Build a case study app”, “case study app for MBA students” and “case-study app”, which went to `simple_app`/15 with the LMS gaps withdrawn. The craft-word lookahead only saw whitespace, so “study-app-development” and “study app/development tutorial” slipped through. A first follow-up added `(?<!case[\s-])` and `[\s\-/]+` craft-word separators.

Reviewer FAIL at `b8bcda5fc`: that lookbehind had no word boundary, so “showcase / lowercase / uppercase / briefcase study app” and “Make a showcase study app for Maharashtra board students” were missed and fell back to `complex_app`/58 with LMS gaps — a regression. “case  study app” (double space), “case/study app” and “case, study app” still leaked to `simple_app`. This follow-up uses the word-bounded, variable-length lookbehind `(?<!\bcase[\s\-/,]+)` (JS/Node 22 supports this; the regex is compiled only on the server and is not imported by the Vite client bundle, whose `safari14` target predates variable-length lookbehind). `study[\s-]+` accepts multiple spaces or hyphens so “study  app” captures, without opening a craft-word bypass (`study  app development` / `study  app/development` stay uncaptured). The corpus now also locks showcase/lowercase/uppercase/briefcase, “study  app”, self-study, bible study and a bare “group study app” as captured; double-space/slash/comma case-study forms, `case_study`, `casestudy`, Case/CASE and “group study app with admin” stay uncaptured, along with every earlier opposite-class phrase. Mutations: dropping `\b` turns red, and so does a single-separator lookbehind.

The user asked: “Make study app for Maharashtra board students” (45 characters). The engine correctly named domain=`education` off the unanchored `student` inside “students”.
