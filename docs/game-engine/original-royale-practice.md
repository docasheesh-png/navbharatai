# Original royale practice: experimental first slice

This is a fresh implementation started on main `2667850ab5e80083e28c9aa1fb73341c1f1bfc07`, reconciled with edit/revision safety main `7948bef0b4153035104b19ade063aa4ccfd29ce5`. The previous unmerged prototype and its terminal test evidence could not be recovered. Its historical partial results are not validation of this tree.

## Implemented scope

- Original deterministic bounded offline practice rules with two bots, shrinking safe zone, damage, cooldown, win/loss and restart.
- A Three.js adapter built on the existing generated Game shell, humanoids, character controller, collision and enterable-house kit.
- A React mount with status, restart and the shell's existing keyboard/touch controls.
- An explicit `generate_game_royale` catalog tool and automatic missing-kit dependency resolution.
- Default-OFF `AGENTV3_ORIGINAL_ROYALE` gate (the shared boolean flag parser accepts explicit enabled values). No production configuration changed.
- Explicit composition-root permission requires a known strict durable inventory, new-build lifecycle, no import/edit or existing verified revision, and positively read empty/platform-starter hydrated source. Manual ownership alone is never lifecycle proof.
- Refusal for unknown/nonempty user-owned source snapshots, unrelated requests, named alternate/Athree worlds or an existing Athree module. Transient storage failure is not treated as a missing map.
- Existing generated or edited files use the repository's guarded recipe writer, never blanket replacement. The recipe does not overwrite App.tsx; successful file emission alone is not a playable integration claim.

## Not delivered by this slice

Four/five complete templates, automatic lifecycle-safe template selection, a terrain/Athree adapter, multiplayer servers, vehicles, inventory, realistic human scans, photorealistic rendering, measured mobile performance, production enablement and new pricing are not implemented. No third-party game source/artwork is copied, no artificial build delay and no billing activation is added.

## Acceptance gates

Focused rules/dispatch tests, complete recipe dependency closure, compiled emitted fixture, full current-tree local CI, Firestore safety drills and actual browser/mobile visual acceptance are separate gates. Record each actual result; a source-string assertion is not visual proof and local CI is not hosted CI or deployment. Do not enable or merge on incomplete results.
